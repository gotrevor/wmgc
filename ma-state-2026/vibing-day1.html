Vibing My Way Through Day 1 of MA State 2026

Tournament directing with Claude Code as copilot

I co-directed the 2026 Massachusetts State Go Championship this weekend. I've done this before - the tournament logistics aren't new. What was new: I built custom tooling on the fly, in real-time, as problems emerged.

Not planned. Not spec'd. Vibed.

The Setup

MA State is a two-day AGA-rated tournament. ~30 players, multiple sections, Swiss pairing. We use Leago for pairings and a Google Sheet for registration (via RegFox). The gaps between these systems are where the friction lives.

Yesterday: Sign-In Sheets

Day before the tournament. Need sign-in sheets for check-in. The data lives in Leago. The format I need: printable PDF with player names, sections, check boxes.

Old me: Export to Excel, massage data, format manually, print.

New me: "Hey Claude, I need sign-in sheets from the Leago data."

Twenty minutes later: a Python script that pulls player data, groups by section, generates clean HTML, converts to PDF.

Was this faster than Excel? Honestly, not by much for a one-off. I've done the Excel dance many times. But now I have a reusable script. Next tournament: instant. The trade-off is less fine-grained control than a spreadsheet - but speed wins when you're doing this repeatedly.

Today: Crosstab Standings

Round 3 ends. Players want to know where they stand. Leago shows pairings but the standings display is... minimal. I want a proper crosstab - the grid showing who played whom and results.

"Can you pull the Leago data and generate a crosstab?"

Leago's API isn't documented, but the web interface makes API calls. We sniffed the endpoints, figured out the data structure, built a script that generates tournament standings with:

  • Player names and current scores
  • Full game results grid
  • McMahon scores (upper section)
  • Tiebreakers

Printed it. Posted it on the wall. Players gathered around. Tournament feels more real when you can see the whole picture.

Today: Prize CSV

Tournament ends. Need to submit results to AGA and distribute prizes. Different prize pools for different sections. Need to verify AGA IDs against the official TDList.

"Generate a prize CSV from final standings."

Script pulls final results, cross-references AGA IDs, calculates prize distribution, outputs in the format needed for the prize coordinator. Caught two players with mismatched IDs before submission.

The Meta-Observation

This was hard. Different-hard than programming, but fully engaging. I wasn't passively prompting - I was thinking through problems, recognizing patterns, steering toward solutions. The AI handled the syntax; I handled the semantics.

Karpathy called it "vibing" - the sense that you're collaborating with something that gets what you mean. That's real. But vibing doesn't mean passive. It means your expertise operates at a different level: knowing what to ask for, recognizing when the answer is wrong, sensing when the solution is overcomplicated.

The Tools

All living in my personal toolkit now:

  • Sign-in sheet generator - Leago → printable PDF
  • Crosstab standings - Leago → full tournament grid
  • Prize CSV - Final standings → AGA submission format
  • AGA ID validator - Cross-reference against TDList

Each one: ~30 minutes from "I need this" to "it works." Each one: reusable next tournament.

The Point

Tournament directors don't need to be programmers. But tournament directors who can program - or who can vibe effectively with AI that programs - can eliminate friction that's plagued the community for years.

The gap between "what the existing tools do" and "what I actually need" has always been filled by manual labor. Now it's filled by conversation.

That's the shift.

Trevor Morris co-directed the 2026 MA State Championship with Nick Bonner. He serves on the AGA Board of Directors and is co-directing the 2026 US Go Congress in Boston.
